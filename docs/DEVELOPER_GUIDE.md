## 1. Project in one page

**Question.** In the IBL mouse task the block prior (80/20 vs 20/80) is never cued, yet mice use it. Which computational route does an
inferred prior take through a drift-diffusion model (DDM)?

| Model | Prior enters as | Predicted Conditional Bias Function (CBF) over RT |
|---|---|---|
| M1 | start point `x(0) = a z prior` | falling (biggest effect on fast responses) |
| M2 | drift offset `v_b prior` | flat |
| M3 | dynamic drift `prior b_max t/(t+tau_b)` | rising |

**Claims.** C1: which of M1/M2/M3 wins (BIC across 10 mice and CBF shape). C2: do mice show urgency (a bound that collapses with time,
Weibull `a(t) = a exp(-(t/lam)^gamma)`) and does the C1 answer survive it?

**Tracks.** Track A (Parth Dhodapkar): simulator, QMP fitter, recovery studies. Track B (Joshua Koilpillai): IBL data, empirical
behaviour, and (Week 3) the C2 analysis. Parth was unavailable in Week 3, so Joshua also ran Parth's C1 fits; that code is in
`src/optimization/c1.py` and `run_c1.py`. `plan.md` is the original schedule, `README.md` the user-facing summary with results.

**Status.**
| Week | Track A | Track B | State |
|---|---|---|---|
| 1 | simulator, boundaries | IBL ingestion, 10-mouse cohort | done |
| 2 | QMP + Nelder-Mead, recovery code | psychometrics, chronometrics, CBF, heterogeneity, notebook | done; plan-scale recovery run in Week 3 |
| 3 | C1: fit M1/M2/M3 to the mice | C2: fixed vs Weibull bounds, invariance, RT tail | done (sections 8 and 9) |
| 3+ | robust C1 (v2): lapse mixture, inferred prior, 3 seeds, common-seed re-scoring, calibrated CBF test | | code done; Ada run pending (README section 6) |
| 4 | publication figures, clean repo | report, posterior predictive checks (joint) | open |

Machine used: WSL2, 20 logical cores, 7.7 GB RAM. **Each fit worker needs about 350 MB**, so 12 workers is the practical maximum on 7 GB.
The repository sits on NTFS (`/mnt/c`), which is slow for many small files; keep `--n-jobs` at or below 12.

## 4. The data contract and conventions

Every trial table (IBL data, simulator output, mock data) has exactly these columns (plan §3.1; checked by `validate_contract`):

| column | meaning |
|---|---|
| `subject_id` | mouse or simulation id |
| `trial_idx` | 0..N-1 in time order |
| `contrast` | signed contrast, right minus left, in [-1, 1] |
| `prior` | +1 right-biased block (P(left stimulus) = 0.2), -1 left-biased block (0.8) |
| `prev_choice` | previous trial's choice, -1/+1; 0 at session start and after a no-go |
| `choice` | +1 right, -1 left |
| `rt` | seconds from stimulus onset to wheel-threshold crossing (`response_times - stimOn_times`) |

Conventions that bite if forgotten:
* **ΔBIC = BIC(model) − BIC(reference); negative = the model is better.** Same for NLL, RMSE. In C2, `dbic_weibull_vs_fixed < 0` means the collapsing bound wins.
* **BIC is only comparable within one data set and one likelihood.** The 2.5 s and 5.0 s cohorts contain different trials, and the C1 and the
  truncation-aware likelihoods score different quantities. Compare ΔBIC between variants, never BIC.
* **Replicate seeds.** Each (mouse, model, bound) is fitted from two seeds (12345, 777) and the lowest-BIC run is kept (`collapse_replicates`);
  the spread between seeds is the optimizer-noise estimate (pooled SD about 250 BIC in C1). A difference smaller than `max(10, 2.8 x SD)` is "inconclusive" per mouse.
  Group-level (across-mouse) tests are the reliable statements, per-mouse winners are not.
* The 2.5 s and 5.0 s cohorts are both filtered to `0.1 s <= rt <= cutoff`; trials slower than 2.5 s are 6-23% of a mouse's responses, slower than 5 s 2-9%.

## 5. Track B, data pipeline (`src/data`)

* `ibl_loader.py`: connects to the public IBL Alyx server (shared public credentials, no registration) with `ONE-api`, lists standard `biasedChoiceWorld`
  training sessions, downloads `_ibl_trials.table.pqt` per session into `data/raw/ONE/` (git-ignored, ~170 MB), computes per-session QC and selects mice.
  Selection rule (deterministic): session needs >= 400 trials, both block types, >= 80% accuracy on easy trials (|contrast| >= 0.25); mouse needs >= 5 such
  sessions; ranked by valid trials, at most 2 per lab. **The cohort is frozen** in `data/processed/mice_selection.csv`; `--reselect` is needed to change it.
* `preprocess.py`: `parse_session_trials` converts a raw table to the contract (sign conventions verified against `feedbackType`; IBL codes the wheel
  direction, so `choice = -choice_IBL`), drops the unbiased opening block (p_left = 0.5), no-go and missing-RT trials, `filter_trials` applies the RT window.
  Extra columns kept in `cohort_extended.parquet`: lab, session id/date, `block_pos` (trials since the last block change), `rt_response`, `rt_firstmove`, feedback.
  `rt_firstmove` (first movement) is **not** used as decision time: it is <= 0.1 s on ~45% of responded trials (anticipatory movement, not a random subset).
* `summary.py`: `summary_stats.csv` (per mouse and cohort: counts of trials removed by each filter, accuracy, RT quantiles).
* Outputs: `cohort_rt2p5.*` (229,140 trials, C1), `cohort_rt5p0.*` (245,321 trials, C2), per-mouse files in `rt_2p5/`, `rt_5p0/`.
  Per-mouse trials: 12,455 (CSHL046) to 40,268 (ibl_witten_07).

Change the RT window: `RT_MIN`, `RT_MAX_STANDARD`, `RT_MAX_EXTENDED` in `preprocess.py`, then `python run_track_b.py --process` (~7 min from the cache).
`src/optimization/empirical.py` has its own copy of `RT_MIN` (a test checks they agree).

## 7. The fitting engine (Track A) as the empirical fits use it

* `models/simulator.py`: `DDMSimulator.simulate(params, contrasts, priors, prev_choices, model_type, bound_type)` runs Euler-Maruyama (`dt` = 2 ms in fits) with unit
  noise. Drift `k sign(c)|c|^beta + v_h prev_choice + v_0 [+ v_b prior for M2/JOINT]`; M1/JOINT start point `a z prior`; M3 adds `prior b_max t/(t+tau_b)` to the drift.
  Trial variability: drift ~ N(0, s_v), start point uniform of width `s_z a`. RT = decision time + `t0`. A trial that does not cross by `t_max` gets decision time `t_max`
  and a choice by the sign of its state (so its RT is `t_max + t0`, i.e. beyond the cutoff). `_kernel.py` is the numba loop with one private random stream per trial,
  so a trial's noise does not depend on the parameters (common random numbers, CRN: the objective is smooth enough for Nelder-Mead).
* `models/boundaries.py`: `fixed_boundary`, `weibull_boundary(t, a, lam, gamma, min_boundary=0.05)`.
* `optimization/qmp.py`: QMP loss. For each condition (contrast x prior x previous choice) and choice, observed RTs are cut at the data's own quantiles
  (0.1, 0.3, 0.5, 0.7, 0.9; `quantiles=` changes this); the loss is the multinomial NLL of the observed bin counts under the simulated bin probabilities, with a small Gaussian
  kernel (10 ms) so the objective is continuous. `QMPDataset(window=...)`, `compute_qmp_nll_blocks` see section 9.2.
* `optimization/fit.py`: `DDMFitter` / `fit_ddm`. Search: the initial guess(es) plus `n_screen` Latin-hypercube points are screened, Nelder-Mead runs from the `n_starts` best,
  the winner is polished with `n_restarts` restarts. M3 profiles `tau_b` over (0.15, 0.35, 0.8) because `tau_b` is not identifiable (counted in BIC). Final NLL uses more simulations
  and an independent seed. `PARAM_SPECS` has default bounds; `param_bounds=` overrides them per fit. BIC = 2 NLL + k ln N.
* `optimization/empirical.py`: `fit_cohort` is the one entry point for real mice. `EMPIRICAL_FIT_DEFAULTS` (contrast exponent `beta`, trial variabilities `s_v`, `s_z`, a neutral side-bias `v_0`
  shared by all models, heavy search 80/5/3) were found by piloting; the reasons are in the module docstring. `fit_cohort` runs (mouse, model, bound, seed) jobs in parallel
  (longest first), writes each finished fit to the cache CSV at once and skips finished jobs on re-run. **Changing settings between calls into the same cache is not detected: use a new cache file.**
* `recovery/`: parameter and model recovery (Wilson & Collins 2019); results and verdicts in `results/recovery/recovery_report.md` and the README.

## 8. Week 3, C1: which route does the prior take?

Code: `src/optimization/c1.py` (analysis), `run_c1.py` (CLI), `src/visualization/plots_c1.py`. Outputs: `results/c1/`, `results/figures/c1/`. Full results and caveats: README section 4.
In short: 60 fits (10 mice x M1/M2/M3 x 2 seeds) on the 2.5 s cohort with fixed bounds; per-mouse BIC table (`bic_table`), across-mouse Wilcoxon / t / sign tests with
bootstrap CIs and Holm correction (`pairwise_tests`), model-predicted vs empirical CBF (`predicted_cbf`: each mouse's own trials replayed 20 times through its fit and binned on its empirical

## 9. Week 3, C2: urgency and boundary dynamics

**Plan task (Joshua, Week 3).** Fit Weibull collapsing bounds `a(t) = a exp(-(t/lam)^gamma)` with trial variabilities to the 10 mice; compare fixed vs collapsing under
BIC at the 2.5 s and 5.0 s cutoffs; analyse the RT tail for urgency; verify that the winning C1 prior mechanism is unchanged under collapsing bounds.

Files: `src/optimization/c2.py` (analysis), `src/empirical/tails.py` (model-free tail tools), `src/visualization/plots_c2.py`, `run_c2.py` (CLI),
`scripts/validate_c2_recovery.py`, `scripts/profile_collapse.py`, `scripts/run_c2_all.sh`, `tests/test_c2.py`. Shared engine changes: `qmp.py`, `fit.py`, `empirical.py` (section 9.2).

### 9.1 Three problems the naive approach has, and what was done

| Problem | Why it matters | Fix (where) |
|---|---|---|
| **Fixed is not nested in Weibull.** Track A's default `lam` range is 0.4-3.5, `gamma` 1-4: even at the ceiling the bound has fallen to 77% of `a` at 2.5 s and to the 0.05 floor at 5 s. | "Weibull vs fixed" would compare two different families, and a fixed bound could never be reproduced. | `COLLAPSE_BOUNDS = {"lam": (0.4, 20)}` in `empirical.py`, applied automatically to Weibull fits (`fit_mouse`). With `lam` 20 and `gamma` 4 the collapse is < 1% over 5 s, so fixed is the limit. `PARAM_SPECS` is untouched (Track A's recovery code relies on it). |
| **The C1 likelihood mishandles the RT cut.** 6-23% of a mouse's responses are slower than 2.5 s (2-9% slower than 5 s) and are removed from the data, but the model still simulates them and the QMP loss puts all simulated slow mass into the last bin. Fixed-bound M2 fits to the 2.5 s data predicted only 0.1-3% of RTs > 2.5 s. | The fit is forced to squash its tail, which favours collapsing bounds (and the closing bins of the data are then not a fair target). | Opt-in **truncation-aware likelihood**: `QMPDataset(window=(0.1, cutoff))`, `DDMFitter(rt_window=...)`, `fit_ddm(rt_window=...)`, `fit_mouse(truncate=True)`. The model is scored on its RT distribution *conditional* on the window: bin edges become `[0.1, q1..qk, cutoff]` and the simulated bin probabilities are divided by the in-window mass of the condition (`_qmp_nll_blocks_windowed` in `qmp.py`). Default is off, so every C1 result is unchanged. |
| **Optimizer noise (SD ~250 BIC) exceeds the effect sizes, and the larger model can come out worse than its own special case.** | The recovery check below showed fits ending in local optima +-50 NLL apart in both directions. | (1) every Weibull fit is **warm-started** from the same mouse/seed's fixed solution with three (`lam`, `gamma`) starts (`COLLAPSE_STARTS`; `fit_cohort(init_from=, init_extra=)`; `init_params` may now be a list); (2) a symmetric **polish pass** (phases 3-4 of `run_c2.py fit`) re-optimises the fixed model from the Weibull solution and the Weibull model from that; (3) the best-BIC replicate of each (mouse, model, bound) is kept. After polishing, the largest "Weibull worse than fixed" is +6 NLL (it was +85). |

### 9.2 What changed in the shared engine (all opt-in, defaults unchanged)

* `qmp.py`: `QMPDataset(..., window=None)`; `compute_qmp_nll_blocks` dispatches to `_qmp_nll_blocks_windowed` when the dataset has a window (hard-count and Gaussian-smoothed versions); `compute_qmp_nll` (the groupby version) raises `NotImplementedError` for windowed data.
* `fit.py`: `DDMFitter(rt_window=None)`, `fit_ddm(rt_window=None)`; `init_params` accepts a dict or a list of dicts (all are screened with the Latin-hypercube points).
* `empirical.py`: `COLLAPSE_BOUNDS`, `COLLAPSE_STARTS`, `RT_MIN`; `fit_mouse(truncate=False, rt_min=0.1)` (BIC's N counts only in-window trials); `fit_cohort(init_from=None, init_extra=None)` and `_warm_starts`; every result row now has a `truncated` column.
* `tests/test_c2.py` checks that the default likelihood and parameter sets are unchanged and that the windowed NLL is lowest at the true parameters.

| Variant | Cutoff | Likelihood | Models | Purpose |
|---|---|---|---|---|
| `trunc_2p5` | 2.5 s | truncation-aware | M2 | fixed vs collapsing, standard cutoff |
| `trunc_5p0` | 5.0 s | truncation-aware | M2 | fixed vs collapsing, extended cutoff, tail analysis |

### 9.4 Fit procedure (`run_c2.py fit`, per variant)

1. Fixed fits, cold start, seeds 12345 and 777.
2. Weibull fits, same seeds, warm-started from phase 1 (fixed solution + three collapse starts).
3. Polish the fixed fit from the Weibull solution (no screening, 1 start, 2 restarts). Stored with seed + 1,000,000.
4. Polish the Weibull fit from the polished fixed solution (3 collapse starts, no screening, 2 restarts). Same seed offset.

`--no-polish` skips 3-4. Replicates are collapsed to the best BIC in `c1.collapse_replicates`; the run-to-run SD reported in the tables uses **only the independent seeds** (offset replicates are not independent).
All phases resume from the cache, so after an interruption just re-run the command.

Figures (`results/figures/c2/`): `c2_bound_comparison_M2.png`, `c2_<variant>_fitted_bounds.png`, `c2_<variant>_invariance.png`, `c2_<variant>_cbf_overlay_{fixed,weibull}.png`, `c2_<variant>_tail_diagnostics.png`, `c2_<variant>_tail_by_mouse.png`.

How the tail statistics work (`src/empirical/tails.py`): survival `P(RT > t)`; discrete hazard per window `-ln(1 - events/at_risk)/width` (the exact piecewise-constant estimator; the naive
`events/at_risk/width` understates wide windows); late/early hazard ratio (2.5-4 s over 1-2 s); accuracy for |contrast| >= 25% in fixed RT windows. Urgency predicts a rising late hazard
and accuracy falling toward chance; drift variability and disengaged trials lower the late hazard. Because the data are cut at the cutoff, late hazards are inflated by the truncation itself, so **data are
only ever compared with model RTs cut to the same window** (`simulate_from_fit` does this).

### 9.6 Validation (read this before trusting a per-mouse result)

`scripts/validate_c2_recovery.py` simulates M2 data with a known bound (parameters from the C1 fits, the real design of NYU-09, 12,000 trials, filtered like the real data), fits it with the real pipeline
(phases 1-2, no polish) and records which bound wins. Four datasets per generating process; results in `results/c2/validation/`:

| Generating process | 2.5 s, C1 likelihood | 2.5 s, truncation-aware | 5.0 s, truncation-aware |
|---|---|---|---|
| Weibull (a(t)/a = 0.85 at 1 s, 0.37 at 2.5 s) | Weibull wins 4/4, median lam 2.5 | 4/4, lam 3.4 | 4/4, lam 3.6 |
| fixed | 1/4 wins | 2/4 wins (mean dBIC +4) | 1/4 wins, 0/4 by > 10 (mean +9, median lam 14) |
| fixed + 8% slow "disengaged" trials | 1/4 | 3/4 (2 by > 10) | 0/4 (mean +18) |

Reading: a real collapse is found at every cutoff; **at the 2.5 s cutoff a fixed bound is called collapsing in 25-75% of datasets** (convergence noise and tail contamination), at 5.0 s no fixed-bound dataset won by more than 10 BIC.
So 2.5 s per-mouse "collapsing wins" are not evidence; the 5.0 s result is the reliable one. Small n (4 per cell): this is a calibration check, not a power study.
It also exposed the +-50 NLL convergence noise in both directions that the polish pass addresses (the validation itself was run before the polish pass existed).

`scripts/profile_collapse.py` fixes `lam` on a grid (`gamma` and all else free) for two mice at 5.0 s (`results/c2/c2_collapse_profile_5.csv`): any collapse that starts before ~3 s is rejected overwhelmingly
(delta NLL +650 to +12,000 for `lam` <= 3), and the likelihood is flat for `lam` >= 5 (bound still ~94% of `a` at 2.5 s), so only a late, mild collapse could hide there.

### 9.8 Results

Everything below is from `results/c2/c2_report.md` and the tables it points to (M2, 10 mice; delta = Weibull minus fixed, negative = collapsing better; 'decisive' needs |delta BIC| above the variant's noise threshold, 610-1270, so **no single mouse is decisive in any variant**; the statements are group-level).

**Fixed vs collapsing bound**

| Variant | mean ΔBIC [bootstrap 95% CI] | mice with collapse better / fixed better | Wilcoxon p | mice whose fitted bound has fallen below 95% of `a` by 2.5 s |
|---|---|---|---|---|
| `trunc_5p0` (headline) | **+12.1 [3.5, 18.1]** | 1 / 9 | 0.049 | **0 of 10** (all `lam` at the ceiling, bound 100% of `a`) |
| `trunc_2p5` | -10.6 [-44, 19] | 3 / 7 | 1.0 | 3 (CSHL046, ZM_1743, KS021) |
| `c1like_2p5` | +14.4 [-1.9, 24.2] | 1 / 9 | 0.084 | 0 |
| `tail_5p0` (tail-weighted) | -94 [-224, 19] | 5 / 5 | 0.63 | 3 (CSHL046, CSH_ZAD_002, NYU-09; `lam` about 5 s, bound 89-94% at 2.5 s, ~37% at 5 s) |

* At 5.0 s every mouse's Weibull fit goes to the fixed-bound limit, and BIC then prefers the fixed bound by about the two-parameter penalty (+19 to +21): **no evidence for urgency**.
* At 2.5 s a few mice look collapsing, but the validation (section 9.6) shows that 25-75% of fixed-bound datasets look like that at this cutoff; the ranking of mice does not carry over to 5.0 s (Spearman 0.09, `c2_variant_consistency.csv`).
* With the tail-weighted likelihood 3-4 mice prefer a late, mild collapse (`lam` about 5 s) by 85-500 BIC, but three other mice show the nested Weibull worse than fixed by up to 44 NLL (convergence failures), the group mean is not significant, and the collapse barely changes the tail fit (mean survival error 0.031 -> 0.030, p = 0.08). Treat it as a weak, heterogeneous signal in 3 mice at most.
* Collapse before about 3 s is excluded for the profiled mice (NYU-09, KS019: delta NLL +650 to +12,000).

**Invariance of the C1 conclusion** (`c1like_2p5`, same likelihood as C1; polished fits, so the fixed-bound numbers differ slightly from the C1 report's)

| Contrast (delta BIC, mean over mice) | fixed bound | Weibull bound | shift [95% CI] | shift as % of the fixed effect |
|---|---|---|---|---|
| M1 - M2 | +318 (Holm p 0.039; M1 worse in 9/10) | +322 (Holm p 0.039; 9/10) | +3.6 [-8, 21] | +1% [-2.6%, +6.5%] |
| M3 - M2 | -22 (p 0.92; not separable) | -23 (p 0.70) | -1.0 [-18, 19] | n/a (no effect to preserve) |
| M1 - M3 | +340 (Holm p 0.006; 10/10) | +345 (Holm p 0.006; 10/10) | +4.7 [-5, 18] | +1% [-1.6%, +5.2%] |

Per-mouse deltas agree across bounds (Spearman 0.96 / 0.93 / 0.93, same sign in 10 / 9 / 10 mice); the per-mouse BIC winner is the same in 9/10 (CSHL046, the one mouse whose Weibull fit collapses, flips M3 -> M2). The three-statement verdict is identical:
M1 rejected, M2 vs M3 not separable by BIC, model-predicted CBF closest to the data for M2 (mean RMSE 0.076 / 0.079 for M2 vs 0.159 / 0.158 for M1 and 0.100 / 0.100 for M3, fixed / Weibull).
**Caveat:** this is close to trivial because the Weibull fits sit at the fixed-bound limit; it shows the C1 answer does not depend on the bound family, not that it survives real urgency.

**RT tail** (`trunc_5p0`, model M2, data minus model RTs cut to the same 0.1-5 s window; `tail_signed_tests.csv`)

| Statistic (data - fixed-bound model) | mean | mice with data > model | Wilcoxon p |
|---|---|---|---|
| late/early hazard ratio (log) | +0.41 | 10/10 | 0.002 |
| accuracy for RT > 2 s (|contrast| >= 25%) | +0.17 | 9/10 | 0.004 |
| fraction of RTs > 2.5 s | +0.047 | 10/10 | 0.002 |

The mice have a heavier slow tail than the model (median 2.9x the predicted fraction beyond 2.5 s), a late hazard that rises more, and **higher** accuracy in slow responses (0.56-0.88 vs the model's 0.53-0.66). Urgency would lighten the tail and push late accuracy toward chance, so the tail contradicts rather than supports it;
and the Weibull model reproduces the tail no better than the fixed one (survival error 0.035 vs 0.035; tail-weighted fit 0.030 vs 0.031). The extra slow, still-accurate responses look like a separate slow, stimulus-driven or disengaged component that the model class lacks.

**Verdict.** No group-level evidence for a collapsing bound (urgency) in these mice; the C1 conclusion (prior enters as a drift/choice bias, M1 rejected, M3 not separable by BIC but disfavoured by the CBF) does not depend on the bound family.
Open: a heavy accurate slow tail, and a possible late collapse in 3 of 10 mice that only a tail-weighted likelihood sees.


### 9.9 Limitations

* Optimizer noise: pooled run-to-run SD is 220-390 BIC per fit depending on variant, so per-mouse winners are unreliable; use the across-mouse tests. The polish pass reduces but does not remove it.
* The 2.5 s cutoff is unreliable for per-mouse collapse claims (section 9.6).
* The standard QMP has one bin for the slowest 10% of RTs, so it barely constrains the tail; `tail_5p0` is the check for that.
* The invariance test (`c1like_2p5`) is partly trivial: when every Weibull fit sits at the fixed-bound limit the two analyses are the same model. A stronger test needs mice that do collapse (see the optional `trunc_2p5 --models M1 M3` run).
* The model family has no lapse or fast-guess process; the four lapse-affected mice (KS019, KS021, CSH_ZAD_002, NYU-01) are mis-specified (README, C1), and `s_z` / `t0` hit their search bounds in most mice.
* The models cannot reproduce the heavy slow tail (data have a median 2.9x the predicted fraction of RTs > 2.5 s); a disengagement component would be the natural extension and would also change C1.

| I want to | Do this |
|---|---|
| change the RT cutoffs | `RT_MIN/RT_MAX_*` in `src/data/preprocess.py`, `python run_track_b.py --process`; then new cohort files -> refit (new cache files); `rt_max` in `VARIANTS` of `run_c2.py` |
| add a C2 variant (other cutoff, quantiles, bounds, model set) | add an entry to `VARIANTS` and `LABELS` in `run_c2.py` (`cohort`, `rt_max`, `truncate`, `models`, optional `quantiles`, `param_bounds`, `reference`); `python run_c2.py fit --variant <name>`; `analyze` picks it up automatically |
| use more replicate seeds | `--seeds 12345 777 42` (finished seeds are skipped); the polish seeds follow (`seed + 1_000_000`) |
| change the optimizer effort | `EMPIRICAL_FIT_DEFAULTS` in `empirical.py` (affects every variant: use new cache files) or `SMOKE_FIT` / `POLISH_FIT` in `run_c2.py` |
| change the bounds of a parameter for the fits | pass `param_bounds={...}` to `fit_cohort` (see `WIDE_BOUNDS`, `COLLAPSE_BOUNDS`); do not edit `PARAM_SPECS` unless Track A's recovery should change too |
| change the decisive-evidence rule | `DECISIVE_MIN_DELTA`, `DECISIVE_SD_MULT` in `c1.py` |
| change the tail windows | `tails.EARLY_WINDOW`, `LATE_WINDOW`, `DEFAULT_*` grids; `tail_summary` hard-codes the accuracy windows 0.1-1 / 1-2 / 2-5 s |
| add a boundary family (e.g. linear collapse) | add the function to `models/boundaries.py` and the factory `get_boundary_function`; its parameters to `PARAM_SPECS`/`SIMPLEX_STEPS` and `DDMFitter._determine_param_names`; pass them in `DDMSimulator.simulate`; use `bound` names in `c2.BOUNDS` |
| add a prior mechanism | extend `DDMSimulator.simulate` (drift/start-point/bias term), `_determine_param_names`, `c1.MODELS/MODEL_LABELS/MODEL_SHAPE`, the colours in `plots_c1.py` |
| re-run everything C2 | `rm results/c2/c2_fits_*.csv` then `bash scripts/run_c2_all.sh 12` (about 9-10 h with the tail variant) |
| run only the analysis after a code change | `python run_c2.py analyze` (reads the caches; ~2.5 min) |

## 12. Pitfalls and troubleshooting

* **Sign of ΔBIC.** Negative = first model better. `dbic_weibull_vs_fixed < 0` = collapsing bound better.
* **Do not compare BIC across variants.** Different data or likelihood. Compare ΔBIC.
* **Stale caches.** `fit_cohort` skips a fit if (subject, model, bound, rt_max, seed) is in the cache, even if you changed settings. New settings = new cache file (or delete rows).
* **Memory.** About 350 MB per worker; at 12 workers plus an editor the machine had ~2.5 GB free. Do not run two large jobs at once.
* **Laptop sleep** pauses WSL2; runs resume from the cache. A finished-run marker is not written for interrupted runs: re-run the same command.
* **pandas 3 is strict about dtypes**: assigning int64 values into an int8 column (`choice`) raises; cast with `.astype(np.int8)`.
* **`lam` at its ceiling (20) means "no collapse"**, not a failed fit; ΔBIC is then about the 2-parameter penalty (+19 to +21 for N = 12k-40k).
* **A Weibull fit worse than the fixed fit** (`dnll_weibull_vs_fixed > 0` by more than a few units) is a convergence failure (the models are nested); run the polish phases or more seeds.
* **The hazard of truncated data rises toward the cutoff** whatever the true process; compare with model RTs cut to the same window.
* The repository is on NTFS under WSL2: file I/O is slow, avoid thousands of small files in `results/`.
* `scripts/*.py` insert the repo root into `sys.path`; run them from the repo root or anywhere.
